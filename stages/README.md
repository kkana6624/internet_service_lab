# 段階の進め方

1つの `terraform/` rootと同じlocal Stateを引き継ぐ。別のstageディレクトリでTerraformを実行しない。`config/*.json` は段階の再現条件を記録し、`deploy-stage.sh N` は該当設定の `public_web` を読んで公開範囲を適用する。他のフィールドは段階の期待値を示す教材メタデータで、実際のコンポーネント構成は適用スクリプトのNに応じた分岐が管理する。段階を後戻りする操作は拒否する。公開停止は `stop-public.sh` を使う。

段階タグは未作成。この納品では各段階設定・適用スクリプト・手順から再現する。完成commitへ6つの異なるタグを付けても段階履歴にはならない。将来タグを付ける場合は各段階を再現・検証したcommitを選び、証跡manifestへcommitとtagを記録する。設定変更をしたらその時点のcommitを記録し、実測時の版と結び付ける。

| 段階 | 目的 | 次に進む条件 |
|---|---|---|
| [01](01-infrastructure.md) | 制限された2 VM | SSHホスト鍵確認・cloud-init完了 |
| [02](02-wordpress.md) | アプリとデータの境界 | WordPress初期設定完了・永続化確認 |
| [03](03-observability.md) | 正常・異常を分けて観測 | 同条件比較・復旧確認 |
| [04](04-public.md) | Webのみ公開 | 実観測期間を記録 |
| [05](05-secure.md) | 通信制御と入口保護 | 許可と拒否を実測 |
| [06](06-cleanup.md) | 廃止・残存物 | 必要データ退避・OCI残存確認 |

当日の受講者は予想を書き、事前に取得した画面・差分・ログを見て理由を説明する。画面が未取得なら実装設定を読んで考察し、実測の結果として提示しない。各段階の生ログは `.private/evidence/`、加工済み教材は `docs/evidence/stepNN/` に置く。
